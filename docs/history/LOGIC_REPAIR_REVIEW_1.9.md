# 1.9 — lead-engineer and lead-developer repair disposition

## Method and release boundary

The earlier 1.8 review independently reproduced five Android interaction failures and five JavaScript contract failures. A green counterexample test then meant the bad behavior was reproduced. In 1.9 those assertions were inverted to require the corrected contract, supplemented with missing callbacks, queue pressure, editor identity, import rollback/undo, Activity-independent completion, stale media ownership, live native bounds and API-34 public Downloads fixtures. Original evidence was not overwritten to make a regression look successful.

The design review traces ownership and state transitions across native input, asynchronous JavaScript, navigation, full screen, UI panels, editor sessions, bookmarks and renderer recovery. The implementation review checks actual actions/results and failure exits, not only warnings or compilation. The final release uses a frozen source manifest and packaged-asset comparison. Remaining platform/player boundaries are explicit below.

## Design contracts now implemented

1. A document owns its evaluations, fullscreen transition, media reports and field discovery. Navigation invalidates older work.
2. A playback intent owns all Play-repair taps and relative-seek bursts. Pause, keyboard entry, backgrounding and target replacement cancel older work. Seek has one in-flight operation and a bounded coalesced queue.
3. An editor session is pinned to document/frame/field. Native key events remain the ordinary transport; unqualified old reports cannot migrate the editor.
4. Bookmark transactions belong to the application/store, not a WebView or Activity. Import completion requires a durable commit; UI reads use an immutable published snapshot. Backup destinations must be explicitly portable or report failure.
5. Generic site enhancement is bounded and reversible; protected site workarounds are not rewritten to accommodate it.

## Preserved and deliberately not “fixed”

- Original `flixer_image_guard.js` and `popup_guard.js` remain protected; the native Flixer request filtering/render-reset block and native dark-mode strategy retain their original fingerprints.
- The dormant Flixer `virtualize()` helper was not activated. Comments alone do not establish that it is safe or in use.
- No continuous listeners/observers/quality wrappers were added to Flixer-owned documents. Passive one-shot controls were repaired and documented separately.
- GPU release before navigation and the force-unmute mapping were retained instead of silently removing safeguards without driver/player evidence.
- No broad all-files storage permission, cross-origin message editing bypass, SDK/dependency jump or user-requested confirmation dialog was introduced.

## Acceptance honesty

This is an actual code repair and installable release, not another review-only deliverable. The reproduced state defects have executable regression contracts. It is still not a proof that no defects exist, nor that every site works on the target Fire TV. The unresolved rows above prevent an honest “every recommendation completely solved” or “bug-free and hardware-approved” claim. They are retained constraints, not hidden behind passing test counts.
